# 사람 브라우저 중앙 백엔드

Railway 서비스 한 개와 `/data` 영구 볼륨의 SQLite로 공개 댓글·질문·평가·판단을 저장합니다. 웹 탐색은 휴대폰에서 실행하며 서버는 웹사이트를 대신 열지 않습니다. 분산망과 AI는 이번 범위에서 제외했습니다.

## 공개 API

기본 주소: https://human-browser-production.up.railway.app

- `GET /healthz`: DB 접근을 포함한 상태 확인
- `GET /v1/records?url=<URL 인코딩한 원문 주소>`: 해당 주소의 공개 기록, 최신 접수순 25개
- `GET /v1/records?url=…&before=<nextBefore>`: 이전 페이지. `nextBefore: null`이면 끝
- `POST /v1/records`: Android의 서명된 기록 또는 소유자 서명 철회 이벤트 JSON 한 개

조회는 공개이며 게시 권한은 P-256 서명으로 검증합니다. 앱 공통 비밀키나 비밀번호를 배포하지 않습니다. 기기 키는 계정 역할만 하며 실제 사람의 고유성·내용의 진실성을 보증하지 않습니다. 동일 ID와 서명 본문 재전송은 중복 생성하지 않습니다. 같은 ID에 다른 내용은 409입니다.

서명 검증 대상은 UTF-8 `signedPayload` 원문입니다. 공개 봉투의 각 필드가 서명 본문과 같은지, 공개키 지문·인용 해시·P-256 서명이 유효한지 확인합니다. Android 실험 프로토콜을 유지하며 Mac과 아직 호환되지 않습니다.

답변·평가·연결의 `targetId`는 이미 공개된 정확한 기록이어야 합니다. 대상 개인 기록을 자동 공개하지 않습니다. 철회는 원작성자 키만 가능하며 원본과 철회 이벤트를 보존하고 공개 목록에서 원본을 숨깁니다. 단말에서 저장·복사한 사본은 회수할 수 없습니다. 완전 삭제·관리자 처리 UI는 후속 작업입니다.

## 공개 범위와 비용 제한

기존 개인 기록·초안은 자동 업로드하지 않습니다. 사용자가 기록별 공개 확인을 해야 전송합니다. 공개 조회 모드에서는 현재 페이지 URL을 API로 전달합니다. 앱이 생성하는 공개키 지문은 게시물을 서로 연결할 수 있는 가명 식별자입니다. 앱 서버 로그에 의견·URL·IP를 출력하지 않지만 Railway의 인프라 로그 정책은 별도입니다.

요청 본문 256 KiB, 필드 길이 제한, 조회 페이지 25개, IP별 분당 120회, 기기 키별 하루 신규 기록 200개, 전체 하루 5,000개, 원기록 총 100,000개 제한을 둡니다. 철회와 동일 기록 재전송은 기록 용량 한도에서 제외합니다. 키를 많이 만드는 공격을 사람 인증으로 막는 구조는 아직 아니며 공개 대규모 출시는 별도 방어가 필요합니다. `BLOCKED_ACTORS` 환경변수의 쉼표 구분 actor ID는 신규 게시만 차단합니다.

## 로컬 실행·시험

Node 22.14 이상(배포 Node 24), 외부 npm 의존성 없음.

```sh
node --test tests/api/*.test.mjs
DATA_DIR=./work/api-data PORT=8080 node services/api/server.mjs
```

시험은 서명 위조·봉투 변조·잘못된 필드·중복·ID 충돌·출처 분리·다른 키의 철회·대상 기록 연결·용량 제한·페이지 나누기·DB 재개방·실제 HTTP 흐름을 검사합니다. 입력은 모두 합성 데이터입니다.

## Railway 운영

GitHub `wilcoco/human-browser`의 `main`과 연결. 저장소 루트 `railway.json`이 `services/api/Dockerfile`을 지정합니다. `/data` 볼륨을 서비스에 연결해야 합니다. `NODE_ENV=production`, `DATA_DIR=/data`, `PORT=8080`은 Docker 이미지 기본값입니다. DB 파일은 `/data/human-browser.sqlite3`이며 WAL/FULL 동기화와 변경 금지 트리거를 사용합니다. 볼륨은 재배포 시 유지되지만 백업과는 다릅니다.

단일 볼륨·단일 인스턴스 구성이므로 무중단 다중 복제·수평 확장은 지원하지 않습니다. 재시작 중 앱 요청은 보류 후 재전송합니다. 백업은 Railway 볼륨 백업 기능으로 설정하고 정기 복구 시험을 해야 합니다. 현재 별도 예약 백업은 아직 설정하지 않았습니다. SQLite 파일 복사 시 WAL을 무시한 단순 파일 복사는 피해야 합니다.

Railway 구독을 변경하거나 유료 추가 상품을 구매하지 않았습니다. 실제 컴퓨팅·저장·네트워크 사용량은 연결된 Railway 계정에 과금됩니다. 요청 제한은 비용 상한 보장이 아닙니다.
